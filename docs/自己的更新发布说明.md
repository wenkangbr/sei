# 发布自己的 Windows 更新

本项目的应用更新源为 `wenkangbr/sei` 的 GitHub Releases。官方镜像已禁用，连接 GitHub 失败时不会改用官方应用安装包。游戏资源包仍沿用原项目的下载地址。

首次使用时，需要先手动安装使用当前源码打包的版本；已经安装的官方版本不会因为源码变化而自动切换到这个更新源。安装前备份 `%APPDATA%\Sei` 中的数据。

## 打包和发布

1. 安装项目要求的 Node.js 22、npm 和本机原生依赖的编译工具，然后在项目目录运行 `npm ci`。
2. 修改 `package.json` 中的版本号，保持严格递增；同步更新 `package-lock.json` 中的项目版本。不要为不同的安装包重复使用同一个版本号。
3. 运行 `npm run typecheck`、`npm test`，然后运行 `npm run dist:win -- --publish never`。首次运行可能下载 Live2D 运行库；若下载失败，打包可能继续但 Live2D 无法显示。
4. 到 GitHub 的 `wenkangbr/sei` 仓库创建 Release，标签必须与版本一致，如版本 `0.6.10` 对应 `v0.6.10`。上传 `release` 目录中该次构建产生的 Windows `.exe`、`latest.yml` 和 `.blockmap` 文件，再发布 Release；草稿不可供应用更新使用。测试版需保留其生成的渠道文件，如 `beta.yml`，并标记为 pre-release。
5. 首次手动安装该安装包；之后发布更高版本时，已安装的修改版才能检查并下载更新。

本地手工发布不要求把源码上传至公开仓库。不要把 `.env`、密钥、角色记忆或其他私人文件上传。当前配置不会对 Windows 安装包签名，Windows 可能显示未知发布者提示。应用需要能够访问 GitHub Releases；如果需要国内镜像，须另行准备属于自己的镜像地址和发布流程。

可选的更新说明及强制安装策略文件为仓库默认分支中的 `version.json` 和 `version-beta.json`；不提供时应用使用默认策略。不要填入官方策略文件，否则可能读取到不属于此版本的更新说明或安装指令。
